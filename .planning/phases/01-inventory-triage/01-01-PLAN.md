    - Each move's log row is written and flushed immediately after that move completes,
      so an interrupted run still has a correct partial log.
    - Name clashes keep the existing `__<id>` rename; nothing is ever overwritten.
    - After a run, every moved file exists at its destination with the expected hash,
      and moved + skipped + blocked == total eligible rows (printed).
    - apply_exceptions.csv is written (header + any blocked/failed rows); it may be empty
      of data rows when there are no exceptions.
  </behavior>
  <action>
    Deliver the complete working file. Make these concrete changes to `main()`:

    1. Add `--inventory` arg defaulting to `docs/inventory/inventory.csv`. Load expected
       hashes into `expected = {row["id"]: row["sha256"]}`.

    2. Before building the plan, load completed ids: if `a.log` exists, read it and build
       `completed_ids = {row["id"] for row in DictReader}`. In the row loop, if an id is in
       `completed_ids`, print `SKIP (already moved) id=<id>` and count it as skipped — do
       NOT add it to `problems` and do NOT treat its missing source as an error.

    3. Before each actual move (in `--apply`), recompute the source SHA-256 (reuse a local
       sha256 helper identical to inventory.py's) and compare to `expected[id]`. On mismatch,
       append `(id, src, "hash mismatch")` to a `blocked` list and continue (do not move).

       header if new, and after EACH successful `shutil.move`, write that row and call
       `f.flush()` immediately.

       exists and its SHA-256 equals the expected value; collect any failures into `blocked`.
       Print a reconciliation line: `moved=<n> skipped=<n> blocked=<n> total=<n>` and assert
       moved + skipped + blocked == total eligible rows.

    6. Write `docs/inventory/apply_exceptions.csv` with columns `id, source, reason` containing
       every blocked/failed row (header always written). Print its path.

    Keep the existing REVIEW-stops-the-run, DATA/DUPLICATE-archive-only, and dry-run behavior.
